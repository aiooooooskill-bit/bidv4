# 响应文件正文编写（tender-body）


Markdown 产物使用标准标题、列表和表格：表头与分隔行列数必须相等；单元格中的字面竖线写为 `\|`；表格前后留空行，备注另起段落。代码块只是示例，不作为实际章节、表格或来源登记。

## 本项目投标主体与资料库

开始写作前读取页面提供的 `work/body/投标主体信息.json`，此文件是本次已确认主体、签字代表及签署日期的固定快照。公司地址、联系电话、传真、企业邮箱、开户信息以及代表姓名与职务，已有值直接使用，不再次向用户提问；缺失常用值或项目专属承诺才集中询问。公司资料按当前项目主体检索，不得使用其他主体的资质、业绩或证件。使用 `read_company_asset` 精读人工核对字段与核对全文；原件机器识别值用于对照，不替代人工核对值。

写作素材全库共用，不区分投标主体。技术方案按已选区间保真注入，随后按本项目招标要求与承诺修订；检查旧项目名、旧客户名和旧主体名残留，禁止把历史承诺直接当作本次承诺。

## 概述

先读 `skills/_shared/path-conventions.md`，按其中的普通文件绝对路径与业务工具参数约定操作。

先读 `skills/_shared/response-guidelines.md`（用户回复规范）。写作依据 = 任务内
当前投标目录（read_artifact默认index查看版本、范围及完整路径；按section读取所需章节、祖先约束与引用的完整来源，按sources补读其它依据。当前上下文已有同版本所需内容则复用，版本变化或内容移出后回读。全局完整JSON只在确有需要时显式full读取）。正文 = 逐节回应的展开：招标要求逐条覆盖、我方事实可溯、方案思路是
唯一真正生成的内容；**承诺类数字（工期/人员/服务承诺/报价口径）只出自用户拍板的
清单，禁止自造**。证据纪律先读 `skills/_shared/evidence-rules.md`。

**父节点内容与事实依据**：普通父节点仅组织子章节，不因标了「正文编写」就另写父正文；待写清单只额外保留实际已有正文或有独立格式内容的父节点。声明函、承诺函等有格式
正文的节点，即使其下挂附件也必须单独生成完整函体，不得只写标题或由附件代替；
仅纯目录容器不建正文。逐段保留原格式中的有效期、真实性、保证金等承诺，未确认字段
留空加批注，不得删掉已有格式条款。成本说明、项目准备情况等非数字事实也须有当前
项目证据：用户只授权继续制作，不等于确认“已完成测算”“备有证明材料”或新增服务承诺。
资料不足只写有依据的编制方法，具体成本、已完成状态及现场承诺加批注待确认。
正文不得声称已具备批注明示尚缺的材料。原文提供说明的准备时间窗口，不得改写为
我方说明持续时长、最低投入或已获确认的执行承诺。

**临时参考件**：用户上传到 sources/、明说「参考/照着」的非招标文件（类似案例、
历史标书范文）。定位 = 写法参考，不是写作依据（依据仍是节点出处
MAND/REQ/SCORE），也不是素材库资产。读取走 parse_document，解析后按 outline
行号取区段，禁止整读全文；用法铁律见 `references/section-writing.md`
「临时参考件」。

页面 build 动作执行完整制作，guide/promises 仍可单独发起。build 先用 build_preparation() 读取真实规划状态：missing 才生成；stale 须先由用户在对应页签核对、编辑并保存，ready 直接复用（含用户已保存的人工修改）。写作指引生成后 validate_body 检查通过，再 build_preparation(stage="guide")；承诺清单生成后 build_preparation(stage="promises")。缺少具体承诺值时一次用 ask_user_question 列全，pending 停轮；页面答复后续接同一会话，先重新读取 build_preparation()，继续未完成阶段，不因规划产出而提前结束整个 build。
规划就绪后逐节生成并合册。build 空范围补写缺失章节并完成 draft 未完成章节（先检查现有文件，合格则校验记录，不盲目覆盖），已有正文无论 ready/stale/unverified 都保留；受影响与失配正文点名提示，不能擅自重写。body 动作已明确指定单章范围时允许更新该章，重建传 replace=true。无需泛化结果确认门。
目录 page_target 为 null 表示不限篇幅；非空是整册规模参考，可按每页约700字估算整体体量，按响应要求、评分重点与章节职责分配篇幅，并把逐节建议字数写入写作指引的缺口/备注列（例如「篇幅建议：约1800字」）。这不是保证 Word 精确页数，不为凑页数重复内容。目录编号由合册统一生成，不写入节标题。
正文产物在当前任务 `work/body/` 下：**每节一个 .docx**（docx 直出——写作与
修订全部经 docx 工具族，模型不直接写 docx 二进制）；写作指引与关键事实承诺
清单仍是 .md（共享文件，主线程维护）。

## 当前阶段与原始要求

仅读取核验时，发起 revise 明确传 read_only=true；程序使用DSH工具限制，并由本轮持久权限拒绝主线程和写手的写入。不能只用自由文本代替只读权限，不从关键词猜授权。普通定向修改仍可写入本轮选定片段。

先按页面本轮原始要求和当前阶段确定工作范围。revise 是定向修订：读取指定现稿，仅修改点名片段，再逐节 validate_body；未要求改动或只读核验时，读取、校验并保留原DOCX字节。缺口、批注、已确认主体信息不构成扩大修改的授权，业务问题只在摘要记录。此分支不建节、不注入、不重建，不进入下述生成步骤。任务中属于主线程的事项不由写手重复。

body/build 的建节、注入和生成步骤仅用于本轮明确要求生成的范围。已有成果保留；本轮选定章节均须按当前文件实际校验后才能报完成，不沿用上轮 ready 代替验收。

## 执行流程

### 第 0 步：查现状

正文格式先读取本项目 `work/analysis/requirements-format.md` 及对应招标原文，调用
`docx_format_rule()`查看当前规则。原文对正文、某级标题或页脚有明确规定时，逐项用
该工具记录字体、磅数字号、倍数/固定行距或页脚格式，并附parse原文路径和逐字引用；
不可把素材的原样式当成招标要求。未规定时正文宋体、小四12磅、1.5倍行距，标题采用
Office/WPS原生Heading1..9逐级下发。合册统一派生稿样式，不覆盖原章节DOCX。
格式规则read返回stale时，按issues逐目标回读当前招标依据并重新设置；当前原文确已取消该目标格式要求时，附当前原文与核对理由，reset=true撤销该目标旧覆盖。其他目标及原正文不变；不能为通过导出跳过仍适用的要求。
默认封面独立且不计页码，目录从第1页开始，目录、正文与已并入附件连续计入总页数；
页脚居中“第 {PAGE}页，共{TOTAL}页”。明确的招标要求优先；如其分节/计数规则超出
工具支持范围，点明具体原文并停止发布，不能悄悄使用默认值。

目录细化后的保全：父节点可同时持有正文和子目录，既有父正文仍须进入合册，不能当纯容器丢弃。
用户已要求归集既有正文时，由完整制作的主线程先用 `docx_section_repartition(path=原正文路径)`
读取正文块顺序和哈希，再按实际内容分配到本节点及子孙标题。所有原文块恰好分配一次，
表格、图片、修订及关系随块保留；不能转写摘要、重复复制整章，也不能创建空子节凑齐目录。
无法确认归属的内容留在原父节点，未有事实的新子节点名缺口，不编造内容。原文件留恢复点，
每个拆分输出仍须校验；拆分与校验不自动视为已完整响应评分。合册前核对父正文、子节及附件
全部被实际消费，未归集旧正文会阻止发布。普通单章修订不扩大到其他章节。

调用 `check_pipeline_state`（无参数），按 `[body]` 段事实裁决：

- 无目录产物 → 引导用户先走 tender-outline，不凭空编目录；
- `[body]` 报「文件无对应目录节点」或「目录产物更新晚于正文」→ 目录已改版：
  向用户点名失配节，由用户裁决重写哪些（用户没裁决前不动这些节）；
- 页面 revise 动作已指定章节与修改要求，按该范围修订，不重建；body 明确要求重建的章节才用 `docx_section_create(replace=true)`。
- 指引已生成且用户没让重写 → 沿用现有指引，继续写未写的节；
- `[untracked]` 有新文件、且用户让它当参考用（「参考这个案例填充/照着写」）→
  **不走 document-parse 的来源确认流**（那是招标来源集合的事），按临时参考件
  处理（定义见概述，用法见 references/section-writing.md「临时参考件」）。

### 第 1 步：写作规划（按页面动作）

guide 单独动作仅完成以下1—3项和原工具检查，产出写作指引后结束本轮；build 动作完成并记录指引后继续承诺清单和正文。promises 动作读取现有指引，整理用户已给的具体值和招标事实，缺少必须由用户决定的值时用 `ask_user_question` 一次列全。pending 后结束本轮；页面答复后续接同一dsh会话。落盘 `work/body/关键事实与承诺.md`（事项｜值｜说明），未给的值记录缺口，不编造。promises 单独动作该清单生成后结束本轮；build 动作记录清单后继续第2步。body 动作先读取 build_preparation，按本步骤补齐缺失准备；复用 ready 文件。两份准备 ready 后只编写页面 sections 指定章节并校验，不合册，不扩展范围。revise 使用现有准备修订指定章。未校验完成的准备可在停止后继续，已确定承诺值必须保留；如需改变，在对应页签列出具体差异，请用户编辑并保存。普通文件 write/edit 只用于主线程当前准备阶段；正文通过 DOCX 工具写入本次允许的章节，其他章节和准备文件不能随单章写作改动。

1. 生成 `work/body/写作指引.md`——格式契约见 `references/guide-format.md`：逐节判
   写作模式（素材修订/格式跟随/推理撰写），search_references 粗匹配素材（素材列
   记块 id，确无素材标【缺】）。**检索必须并行：同一消息并发发出多个
   search_references 调用（每轮 ≤2 个）、按表顺序分轮推进，禁止一节一轮串行**
   （串行会让几十节的整本在开工前多排几十轮模型调用）。缺料即备料对账，
   向用户点名缺什么。
2. **公司材料同轮检索并沉淀进指引缺口列**：涉及公司事实的节（资质证书/基本情况/业绩案例/人员资格/证书复印件），同一轮
   并发跑 `search_company_assets`（doc_type 可过滤资质证书/人员证书等类目）；
   命中的把关键事实写进该行缺口列——`【知识库】材料名（关键数字如注册号/
   有效期照抄原文）`，多条分号分隔，含图的命中注明「含图 N 张」；未命中的维持
   `【缺：xxx】` 点名。缺口列内容随派发自动送达写手（程序透传），是公司事实的
   唯一调度落点——**查到不写进指引＝白查**。
3. **图示列随模式同轮填**：涉及进度/组织/架构/对比
   的节，依据评分表与招标要求里「进度计划/组织架构/图表」类倾向在指引「图示」
   列规划产出项（记法「类型:主题」，类型∈表/分层/辐射/甘特，见
   references/guide-format.md）；无倾向的节写「——」**不为丰富而丰富**（凑数
   表格评委反感）。该列随派发自动送达写手、validate_body 节级对账——
   **不进计划的能力等于不存在**。
4. 用 `validate_body(section="body/写作指引.md")` 检查文件契约，并更新任务进度。页面直接展示已产出的内容，不提示等待核对、确认或回复继续。

### 第 2 步：逐节生成（按指引模式路由，按范围选执行方式）

细则见 `references/section-writing.md`。路由规则与各模式的 docx 工具链：

- **素材修订**（默认模式）：素材先行五步——（派发/指引已给块清单直接用，
  缺块才检索）→ 列使用计划 →
  `docx_section_create` 建节 → `docx_material_inject` 按块 id 保真注入底稿
  （段落/表格/图片零转写，docx 原件专属；块是拷贝授权范围非注入原子——本节
  只需要块内部分章节时传 lines 行号区间只注入相关部分，整块适用则不传；
  非 docx 原件按文本参考自行撰写）→
  `docx_section_read` 拿段落序号 → `docx_section_revise` 定向修订适配本项目
  （旧项目名/公司名/参数按承诺清单改，全部落 Word 修订标记）。
  **docx 原件块禁止跳过注入直接自写**——块内图片/表格原样式只有注入能进正文
  （2026-09-08 实测：整本自写=0 图）；选中内容含图的尤其必须注入。
  素材自带的表格随注入保真进正文；素材没有表格而本节该有（配置清单/对比类），
  用建节 body 的 table 块补建——**表格类内容不用流水句铺**；
- **格式跟随**：按招标文件规定的格式/表格逐项响应——依据节点来源 ID 回
  analysis 表取出处，再按行号读原文的格式要求，不自由发挥结构。**出处原件是
  docx 时优先 `docx_source_inject` 把格式原样拷进节文件**（source=来源文件名，
  lines=出处行号区间；独立格式附件留空 lines 整文件拷），再
  `docx_section_read` 拿段落序号与表格格坐标 → `docx_section_revise` 填空
  （表格空格子 fill、旧值 replace；我方信息按承诺清单填，未定值用
  `docx_comment_add` 加批注记待办）；
  pdf 原件无可拷元素，维持内容一次成形于 `docx_section_create` 的 paragraphs
  （换行分段），微调走 revise；
- **推理撰写**：针对本项目写方案、不联网检索；全文一次成形于建节的
  **body 块序列（段落+表格混排）**——人员配置/里程碑/进度计划/对比类
  内容用表格，**不用流水句铺**（写法示例见 references/section-writing.md
  「推理撰写」）；纯文字节仍可用 paragraphs（换行分段）；局部补充走
  `docx_section_revise` 的 insert_after。指引图示列的计划项逐个产出：普通数据表
  =body 的 table 块、分层/组织架构/甘特/中心辐射/分支回环流程图=`docx_diagram_insert`
  （程序生成，模型只给语义拓扑——流程图 kind=flow 给节点+连线 JSON，程序转
  mermaid 渲染）。**系统界面原型**（图示列计划了「原型:…」的节）用
  `docx_html_figure`——模型只写全部样式内联的 HTML（≤150 行、禁外链禁脚本），
  渲染由应用前端离线完成、产物自动带「界面原型 · 示意图」角标；渲染失败时改用
  文字描述+批注，勿重试。证书复印件等独立图片用 `docx_image_insert` 插入
  （图源路径出自 search_company_assets 命中行的「含图 N 张」提示，PDF 原件可
  按页渲染）。

模板或附件填充的节执行期三分：**格式表格类（投标函/授权书/投标一览表等，
需按招标格式填写的）且出处原件是 docx → 建节后 `docx_source_inject` 整文件
拷原件 + revise 填空，产出节文件**（合册时按树序并进整本）；**物理附件类
（资质证书/营业执照/票据凭证等复印件位）先看指引缺口列的知识库命中——有
原件（含图）的走贴图路径**：建节 + `docx_image_insert` 逐张贴证书图（图源
路径按命中注明的 knowledge/parse/…/images/，PDF 原件可按页渲染；库里没有
的证书 `docx_comment_add` 批注点名待补）；**全无命中→建壳节**：
`docx_section_create` 建节（标题 + 一行贴入位，
如「（此处贴入：营业执照复印件，加盖公章）」——贴上即覆盖、无需删除），
再 `docx_comment_add` 批注点名缺什么材料、由谁提供——**每个附件位在整本里
都必须有落点**，废标级资格件不能只活在收尾汇报里。目录容器跳过、待核验先问
用户。树首「封面」节点照常进指引表与执行（有 docx 样例=格式件拷样例填空；
无样例=排版成形，写法见 references/section-writing.md「封面」；合册自动把它
排成整本首页、独页无页眉页脚）；「目录」节点（tender-outline 规则 11）进
指引表但**不建节不派发——目录页由合册机械生成**。**缺料/待澄清/待核验一律 `docx_comment_add`
加 Word 批注**（锚定相关段落，
写正文继续不阻塞；读视图行尾显示〔批注：…〕、validate_body 清点）——**正文里
禁止写【待补】【待澄清】占位文字**（会随交付稿出去，validate_body 判不过、
合册点名）。

执行方式按用户指定的范围分（派发分组由你判断——check_pipeline_state 的
  `[body]` 段只给待写节清单：每节一行，带模式与素材块数）：

- **单节**：主线程就地写（写前浏览同层已写节的开头段，避免重复表达）；
- **多节（指定的章/节 ≥2）/整本（用户说全部/都写，或开工指令覆盖全部）**：把
  待写节规划成若干**任务**（一个任务=一个子代理、写一节或多节）后并发派发
  `tender-body-writer`，**同一消息内的多个派发同时执行**（不要逐个串行发起）；
  一波返回、一句话汇报、再派下一波（波间汇报的同一轮先用 update_task_progress 回写
  任务清单——面板给用户看的进度承诺，停在旧阶段就是谎言；至少把已完成节数
  并进对应项的进度）。分组怎么定（按 `[body]` **待写节清单**的每节模式与素材
  块数自行判断）：
  - **格式跟随/模板填充类轻节可捆**：3~5 个捆成一个任务连写（它们多是拷原件
    +填空，单独各占一个并发位不划算——一波的耗时由最慢的任务决定，轻节捆组
    省的是时间）；**推理撰写/素材多的重节单独成任务**；单任务不超过 ~5 节、
    素材块多的节别互捆（捆太大=自造长尾，整波等它）；
  - **不按一级章节分批**——章内节体量悬殊，按章会被最慢一节钉死整批、先完成
    的子代理干等；也**不按主题分批**（格式件一波、正文一波是同一种扎堆）；
    按运行上下文中的 **DSH 正文派发容量** 分波，同一消息并发派发不超过该容量的
    独立任务；不足一波时按实际任务数派发。
    每节只分配给一个写手，工具执行与子代理激活由 DSH 的现有并发限制调度；
  - **全覆盖自查**：派发前对照待写节清单确认每一节都落进了某个任务，漏节
    只能等下一轮补（收尾对账会点名）。
  派发 description **只写：第一行节名清单**（一节=节名，多节=顿号分隔，
  **逐字抄待写节清单的名字**，如「写 投标函、授权委托书、开标一览表」或
  「写 3.1 项目理解」——子代理卡片标题取首行；不要在首行加说明文字，多个
  节名之外的任何前导语都会让系统拼装失配）**＋第二行起可选的特殊意图**（如
  「重点补移动端表单」；有临时参考件时在意图里给参考路径+行号区间——如
  「参考 <当前任务绝对路径>/work/parse/案例.docx/案例.docx.md 的 L120-L260 写法」，写手自行按区段 read）；其余
  共享上下文——当前任务绝对路径、各节输出路径、指引行、要求清单（依据列 ID 由
  系统解析为要求原文+出处，编号不进派发）、素材块名片、公司材料与缺口
  （指引缺口列原文，含知识库命中事实）、承诺清单全部值、兄弟节开头摘要——
  **由系统在派发时自动补全**（程序拼装——模型罗列的清单实测会塌成五字节名），
  模型无需也不应重复罗列；
- **整本的开工前置**：**开工指令后、首波派发前重调一次 check_pipeline_state**
  ——待写节清单只在指引已生成后产出（第 0 步调用时指引多半还没写，返回里不会
  有清单，别指望那次）。**断点续跑或中断后重新派发前，同样必须重调一次
  check_pipeline_state 对账已写节、已写的节不重派**——中断落在波中间时存档
  会整波回退，凭记忆重派等于把写完的节整轮重写（重派守卫也会拦截无重写意图
  的重复派发）。用户裁决「全部重写」时清单不含已写节，按上面的分组口径对
  待重写节照常规划。

### 第 3 步：自查与全局比对

- 子代理逐节跑 validate_body（节路径 + block_ids；docx 节按接受全部修订后的
  终稿视角校验）；主线程对返回摘要里标记问题的节复查重跑；残留分级——
  **明确旧名（check_name_residue 的元数据级/显式名单）必须清零**，疑似提示
  （素材文件名来源，可能是通用产品术语）逐条核对：旧项目用语替换、确认通用
  则在收尾说明一句；
- 全部节完成后 `validate_body(section="body")` 跑全局承诺比对与节间查重：承诺
  清单每个值未在任何正文出现会被点名（该节未写或值被改写，核对后补落或修正
  清单）；两节内容大面积重叠（同一素材进多节或原文照搬）同样点名——逐对裁决，
  拆块重派或改写其一；
- 待办批注清单（各节 docx_comment_add 落的批注）记录在案，收尾汇报用。

### 第 4 步：合册整本

默认只导出Word，不安装或调用LibreOffice，不生成PDF。目录用原生TOC/PAGEREF域，
标题用原生多级列表，页脚用PAGE和正文末尾书签的PAGEREF域，设置打开时请求自动更新。
实际分页、目录页码与总页数由打开文档的Office/WPS计算；不得声称导出前已完成分页，
也不填写估算数字或旧缓存冒充真实页码。封面独立分节且不计页码，目录从1开始，正文与
实际附件连续编号并共同计入总数。办公软件是否自动执行更新取决于其功能及设置。
合册前机械检查域闭合、标题与书签对应、材料页码目标、连续分节编号；缺少附件对应关系、
正文未齐或待校验时不覆盖旧发布成果。手写目录的纯索引清单由机械目录更新，附注、表格、
批注和正文原件保留。不创建空节凑齐目录或页数。

全部节自查通过后调用 `docx_assemble_volume`（无参数）：按投标目录树序产出
每册一个 `work/body/整本-<程序返回的册目录键>.docx`，直接使用合册回执路径，原始册名在文档中逐字保留（**章节标题按树序自动编号**——格式取
目录产物的编号设置，缺省「1 / 1.1 / 1.1.1」，封面不占序；编号使用 Word/WPS
原生多级列表并关联内建 Heading 1–9，禁止将序号写进标题文字。招标文件明确规定
其他编号时按要求设置；一级章前分页、页脚页码）。
**整本=交付态**：节内修订标记按「接受」压平并入（未接受修订前不再新旧并存；
节文件层修订保留供审阅，改内容回节文件层改）、待办批注原样迁移保留、节内
小标题自动摘出大纲（整本导航窗格/自动目录只剩章节骨架）**并按树深度降级、
原生列表接续节号**（深度 2 节下 H2→H3 并编号 5.1.1 式——参与编号的素材标题与章节
共用多级列表，按正文实际顺序续号，上级增删时下级自动同步；目录沿用相同实际序号，
写手在节文件内维持 H2/H3 习惯、一个号都不写）。返回里的缺失节/
未并入文件/内联占位/节点名自带编号/手写目录页对账不符等警告逐条向用户
点名——「目录页已生成」行说明机械目录页条目数（未产出附件节自动标「另附」）；
手写目录节文件的对账不符时修目录节文件再重新合册。**整本是派生产物**——收尾汇报要说明：改内容回
节文件层改（或让模型改）再重新合册，直接手改整本会被下次合册覆盖。
**合册成功即自动发布为整本标书产物**（每册一条；聊天产物卡与产物面板可
预览/下载；docx 内容未变不重复发布、不刷卡）。

### 第 5 步：收尾汇报

- 逐条点名待办批注清单（缺什么/要用户裁决什么，不可只字不提）；
- **素材异议单独点名**：子代理摘要里带「素材异议」的节，逐条列节名 + 块 id + 理由，
  并给你的建议（换块重写 / 保留 / 该节改推理撰写）。指引的素材列归用户拍板——
  要改就让用户改指引，或经用户同意后由主线程改素材列再重派该节；
- **图示产出情况**：指引图示列计划 N 项 vs 实际产出 M 项
  （表格/图示合计），计划外或未产出的逐项说明原因（validate_body 节级对账
  会点名，这里给结论与处置）；
- 汇报各节完成情况、未写节及原因、每册整本文件路径（引用
  check_pipeline_state 的 `[body]` 事实）；整本已发布为产物，指引用户从
  聊天产物卡或产物面板打开/下载。
- update_task_progress 更新任务进度便签（保持简短）。

## 注意事项

- **章节编号由合册自动生成**（按目录树序）：建节/插标题一律用目录里的原文名、
  不带「第一章」「1.1」等编号前缀（写了会导致合册剥不掉节文件自带标题、出现
  双标题）；节内小标题同样不写数字编号，层级用 Heading 2/3 样式区分；素材
  拷入标题段自带的自动编号由注入/合册程序剥除，无需处理；
- **目录页由合册机械生成**：树里的「目录」节点**不建节文件、不派写手**——
  合册在该位置生成目录页（Word 目录域+缓存章节清单：预览即见清单，
  页码使用原生引用域，由Word/WPS打开时计算；未产出附件节自动标「另附」）；
  前置区（目录节点之前的非封面节点，如编制索引）不占章号，正文从目录后
  第一章起编。用户手写「目录」节文件则优先并入并机械对账（一般不需要）；
- 正文是干净文本：不带任何模型写的头部/元信息（建节只写标题与正文段），
  **正文禁止【待补】【待澄清】等占位文字**（评委要看的是干净文本，打印会原样
  出去）——缺料/待澄清/待核验全走 `docx_comment_add` 批注（批注打印与 PDF
  导出默认不带，Word 审阅侧栏可见）；
- 生成的正文遵守去 AI 腔语言纪律（见 references/section-writing.md「语言
  纪律」节）——素材底稿与拷贝的招标格式件不适用；
- 素材改写后必查残留（行业第一大事故=提交稿残留旧机构名/旧项目名）；
- 写一节前浏览同层已写节的开头段，避免跨节重复表达；
- 引用投标目录用 read_artifact（任务内当前版本），不猜文件路径；
- 表格单元格修订：`docx_section_revise` 按 table/row/col 定位（视图中 T 序号
  + R行C列 格坐标）——replace 改旧值、fill 填空格子；表格插行/删行与嵌套表格
  不支持（在 Word 中改）；
- 独立图片（证书/扫描件/截图）进正文唯一通道=`docx_image_insert`（全宽居中、
  带插入修订标记）；素材块内的图走注入，不经它。
