# 灵燕业务融合到dsh原生Agent：隔离验证方案

日期：2026-10-11。遵循 [AGENTS.md](../AGENTS.md)，关联 [PLAN.md](../PLAN.md)。本文件为方案；首轮执行结果见 [DSH-NATIVE-VERIFICATION.md](DSH-NATIVE-VERIFICATION.md)。按用户最新授权使用已配置本地模型，验证工程链路，不审核模型生成内容。

8项官方插件的适用范围、源码证据、互相影响和采用判断见 [DSH-OFFICIAL-PLUGIN-ASSESSMENT.md](DSH-OFFICIAL-PLUGIN-ASSESSMENT.md)。不以全局开启官方插件替代业务接入；先用Agent循环与原生子智能体承接灵燕执行单元。

## 命题与判断

在不启动、不导入灵燕运行循环、不访问3188的条件下，dsh原生Agent能否按灵燕业务方法接受原页面操作，执行原工具，保存原成果并在原页面展示，包括主子Agent、具体选择、停止、恢复和下载。

反证优先：dsh持久会话不等于LangGraph节点检查点；原Python工具依赖任务上下文、数据库和LangChain装饰器；图片模型与原OCR的分页、预算和效果不同；复制整套中间件会重复实现dsh已有能力。不能把“插件能注册”“页面能读夹具”当成完整融合成功。

支持证据：本机dsh提供原生Agent、子Agent、模型、技能、工具、附件与持久会话；灵燕已提供成熟业务技能和文档工具。统一宿主可以删除重复模型配置和独立运行服务。

判断：继续采用dsh原生运行方案，沿用灵燕业务逻辑。运行核心及原页面一节解读已有真实端到端证据，完整业务迁移尚未完成。工具作用域、项目内存储或恢复若不满足，记录阻塞并修订组合方式，不假报通过、不回退旧引擎。当前路由未声明图片能力时阻塞扫描件/图片解析，本地数字文档仍可处理。

## 已阅读的子Agent实现与选择

本机版本锁定 `@deepseek-ai/dsh 0.2.0-rc.2`，已检查以下实际实现，不仅参考README：

| 插件/实现 | 已确认的代码行为 | 本项目使用方式 |
|---|---|---|
| [spawn](../node_modules/@deepseek-ai/dsh-subagent-spawn-in-process/lib/index.js) | 注册spawn提供方；新空会话；支持persona、工具过滤、模型选项、深度及结构化输出 | 优先承接灵燕目录写手与正文写手，自足输入，不复制父级全部聊天 |
| [fork](../node_modules/@deepseek-ai/dsh-subagent-fork-in-process/lib/index.js) | 仅复制父级最后一个turn/end之前的完整历史，不包含当前未结束轮次 | 只有确需已完成父级历史时使用；不为“功能更全”默认启用 |
| [共享驱动器](../node_modules/@deepseek-ai/dsh-subagent-in-process-driver/lib/index.js) | 创建真实子Agent、派发followup、等待idle、收集结果；父信号取消子级；资源由handle释放 | 复用创建/取消/结算机制，不自行编写线程池或Agent调度器 |
| [子Agent组合](../node_modules/@deepseek-ai/dsh-subagent/lib/types/child-agent.js) | composeFrom接入父级预设，之后注册子级persona和toolFilter；模型取父级最新请求路由；记录工作区和父子身份 | 灵燕业务工具放在可组合的执行预设；再按角色限制。任意父级临时作用域注册不能假定自动复制 |
| [委派工具](../node_modules/@deepseek-ai/dsh-tool-subagent/lib/index.js) | 通过exec.agent和当前工具signal调用已注册提供方，支持一次性与可续接模式 | 先验证一次性章节/目录任务；只有实际恢复需求要求时才用可续接模式 |

主子Agent使用同一dsh模型选择，不开启另一套子模型设置。子Agent不调用用户提问工具；未决信息返回根执行Agent，由原页面提供具体业务输入。权限、取消与冷恢复的实际可用性仍需V0/V4测试。

当前maxActiveSubagents容量池只约束可续接子级，一次性执行不受该池限制；maxParallelToolCalls也不是全项目子Agent总并发上限。V0/V3先验证单任务再验证两章并行、取消及实际容量边界，不能把设置卡片当作全局并发保证。团队组合包会禁用普通subagent工具，本方案不全局启用该包。

## 目标职责与代码去向

```text
原页面 → dsh插件业务接口 → dsh执行Agent
                            ├─ 灵燕原技能与业务提示词
                            ├─ dsh原生主子Agent/模型/会话
                            └─ 灵燕业务工具 → data成果 → 原页面
只读展示Agent → 同一项目成果与dsh执行状态
```

聊天展示Agent仍只开放查询工具；页面创建的执行Agent默认完整文件权限，不另设项目/任务文件沙箱，不限制来源目录或普通符号链接。两个角色按工具职责区分。后台会话如何呈现由V0核实，不先增加用户入口，不改为聊天驱动操作。

| 原内容 | 保留/调整 | 删除 |
|---|---|---|
| 解析、解读、目录、写作/审查技能及参考文件 | 复制原规则；改工具名、页面输入、路径和OCR说明；保留来源/许可 | 过时配置入口、泛化确认和无需求技能/说明 |
| 目录/正文子Agent提示词与派发输入 | 配置原生persona、任务文件、册/章节范围与工具过滤 | DeepAgents子Agent规格和框架中间件；不逐行搬运 |
| DOCX/PDF解析、目录组装、正文编辑、插图/合册和原工具检查 | 尽量提取原函数；成熟Python工具可按需子进程调用 | 常驻HTTP服务、LangChain装饰器及模型/Agent运行依赖 |
| 来源/成果/资料/版式和业务任务存储 | 保留当前格式、索引及必要操作记录；宿主接口直接访问 | 第二套会话/运行状态、agent.db检查点；不做检查点migration |
| 模型/重试/压缩/能力发现 | 优先使用dsh现有实现；业务重入约束保留 | 独立模型Key/CRUD/探活/复制、注册表及重复运行能力 |
| OCR/VLM | 同模型视觉输入；PDFium分页、Pillow/宿主附件处理 | 百度AK/SK、另选视觉模型及旧OCR fallback |

删除“引擎”不等于丢弃业务源码，也不要求把成熟Python工具重写成JavaScript。工具进程不得启动另一套Agent或调用模型SDK。继续保留MIT许可与来源记录。

## 模型、OCR与数据规则

- 页面有关联dsh会话时取该会话已选模型；没有关联时取宿主已有默认选择。这是明确入口规则，不是调用失败时尝试另一配置。一次运行记录实际provider/model，子Agent和辅助调用默认一致，不复制Key。
- 数字DOCX、文本PDF先本地解析。扫描页/图片才调用同模型视觉输入；混合PDF逐页处理，不重新识别整本文本，不静默漏页。
- 先核查dsh现有模型的图片能力声明，再核查真实端点。官方pi-ai模型`input: [text, image]`使read_image可用；缺声明默认text，read_image会在请求前拒绝。这是既有dsh模型配置，不新增本项目OCR设置。隔离诊断已证明当前同模型图片通路可用，正式配置仍未改；完整OCR仍需接入。声明不是能力探测，不能靠模型名称或占位文本认定成功。
- 保留页序、页码、来源、解析MD、大纲及元信息契约。GIF维持已定首帧文字解析，原动画预览不变。
- 原件100MiB与单图/像素/消息预算分别约束。复用PDFium、Pillow及dsh附件的现有处理，分批并限制内存；不能为了“通过”跳页或把部分识别标成全文件成功。
- 所有项目业务文件、派生图片、执行会话与附件进入根data。dsh JSONL的root、附件服务的dshHome不是cwd；先验证项目作用域绑定，不重配其他项目的全局根，也不自建第二套日志。
- 固定OCR输出只验证传输、分页、聚合、取消、元信息和页面呈现。真实识别准确率、表格还原、费用和耗时不在本轮验收结论中。

## 隔离方式

测试源码留在项目测试目录；夹具、独立测试宿主配置、日志、附件统一放 `data/.validation/<本次标识>/`。使用临时端口，不改写/重启用户3080，不写现有任务或安装版灵燕。浦发成果只读引用或复制为标记清楚的夹具。

使用真实本机dsh Agent loop、子Agent、工具、附件和持久化组合，并复用宿主已配置本地模型。凭证只由官方credentials-local服务读取原存储，不复制到项目，不输出凭证，不创建独立模型入口。不打桩Agent或页面生成入口来证明融合；故障注入若采用固定传输，要单独记录，不能替代真实链路证据。

测试不加载原main/agent、DeepAgents/LangGraph和百度OCR；检查依赖导入、进程及连接，保证无隐藏引擎。通过后同一业务实现接入正式插件，替身只保留在测试中，不另做产品上传页或长期测试壳。结束时只清理本次验证根，保留测试源码、精简截图及结果。

各阶段先跑通一条完整链路再增加能力，不预先全量改写。逻辑一致核对业务阶段、技能规则、工具约束、文件契约及关联，不比较模型生成文本或复制框架内部算法。

V4必须补充的边界：

- 同一运行连续两次具体选择按问题/工具身份关联；页面已提供主文件、角色与章节不重复确认；关弹窗不默认同意。子Agent不能等待用户输入。
- 停止传播到子Agent、模型流及工具进程；网络失败、用户停止、正常结束区分展示。工具未开始、已写文件未记录结果、已完成但回执丢失分别测试；先核对成果/操作记录再重入，不无条件重复副作用。
- 执行Agent跨工作目录、绝对路径、来源目录及普通符号链接读写默认允许；测试仅操作自有夹具。业务动作仍核对选定任务/册/章节、上传文件名契约、同名与清理碰撞及并行版本冲突；这些是数据正确性规则，不是文件权限沙箱。业务动作幂等记录不变成第二套运行状态机。
- 上轮缺陷回归：渲染请求超时、DOCX版本缓存、旧答案、侧栏/插件切换草稿保护、MD出处整格/关联保护、资料失败状态、过时确认/配置指令、迁移测试、生成脚本及无用CSS。
- 多页/混合/坏/密码PDF、图像预算、识别中断不能静默丢页；只读展示Agent不能上传、修改、停止或生成。

## 正式删除清单与结论边界

清理后用最终依赖重新安装/启动，防止旧虚拟环境或缓存掩盖删除遗漏。保留当前业务成果，不导入安装版配置、不迁移检查点、不清空用户data；待删除的孤立运行文件先确认准确归属。
