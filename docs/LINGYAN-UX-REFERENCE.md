日期：2026-10-11。以当前项目 AGENTS.md、既定页面操作流程和用户要求为准。本轮交付的是方案修订，未将以下待实施项标为代码完成。

## 体验与源码范围

## 源码对应与取舍

以下路径均相对上述固定提交；完整链接在source-index中。自动重试、断线、取消失败和保存冲突本轮只核对源码，未在用户App注入故障。

| 场景 | 灵燕源码 | 采用方式 |
|---|---|---|
| 用户化错误首行与技术详情 | `frontend/src/lib/errorText.ts`、`components/ai/ToolStepRow.tsx` | 用中文说明影响及操作，原始错误折叠。优先现有HTTP状态/错误码；不复制未命中便把原文截断上屏的规则，不复制虚拟路径保护提示 |
| 查询失败和空状态 | `components/ErrorCard.tsx`、`components/ChatView.tsx` | 失败不是“尚无数据”；保留已有结果，顶部提示带对应重新读取动作；首载失败显示中性未读取状态 |
| 服务连接、恢复 | `components/SidecarBanner.tsx` | 借鉴顶部单一状态条及恢复反馈；实现绑定dsh宿主实际连接状态，不引入灵燕sidecar重启、日志及诊断流程 |
| 模型自动重试 | `lib/retryNotice.ts`、`hooks/runReducer.ts` | 借鉴尝试次数/倒计时的清晰反馈；仅展示dsh真正提供的重试事件，不在前端新增自动执行，不编造次数或等待时间 |
| 主动停止及停止竞态 | `hooks/useRun.ts`（cancel）、`hooks/runReducer.ts` | 显示正在停止直至服务端终态；主动停止为中性。停止失败解除按钮锁并重新读真值，不把404/409一概当作执行失败 |
| 终态恢复 | `components/ErrorCard.tsx`、`components/ChatView.tsx`、`hooks/useRun.ts`（continueRun） | 只借鉴恢复动作区分。灵燕checkpoint不移植，dsh副作用恢复未通过前，不提供“从断点继续”或“不从零开始”的承诺 |
| 上传进度与失败重试 | `context/FileUpload.tsx`、`components/UploadChips.tsx` | 固定失败项的任务与文件；网络/服务临时失败可重试；非法文件/超限要求更换文件。不在解读/制作/审查栏目下重复报错 |
| 轻量操作反馈 | `context/Toast.tsx` | 正常成功反馈轻量短暂，不留下成功记录清单。持续故障保留在当前任务顶部操作提示；同一事件不反复弹出 |
| 保存状态、冲突与并发 | `hooks/useAutoSave.ts`、`components/editors/SaveStateBar.tsx`、`components/WorkbenchViewer.tsx` | 参考未保存/保存中/已保存的反馈、dirty期间不覆盖及显式版本选择；继续使用当前手动保存。不照搬卸载失败后强制覆盖的行为 |
| 目录无效操作 | `components/processors/DirectoryEditor.tsx`、`directoryTree.ts` | 复用现有纯函数，边界动作禁用或提供具体原因；不静默吞掉非法升降级/移动，不自写第二套目录算法 |
| 具体选择与已回答历史 | `components/ai/InterruptCard.tsx`、`components/ai/RunTrace.tsx` | 只保留实际需要的拆册、承诺值等具体选择，页面作答；按问题身份区分新问题/同问重连，提交失败保留答案 |
| 原件分流、缓存及资源释放 | `components/SourceView.tsx`、`components/preview/*` | 七类原文预览及换文件释放资源按现有组件继续；版本变更使缓存失效。失败提供恢复动作，不把解析稿替代原件 |
| 资料解析重试 | `components/kb/DetailHeader.tsx` | 复用已有重新解析动作及提交中状态；不将解析失败和信息待确认合成一个状态，不引入内容审核门 |

**上传与预览不能混淆**：该提交的 `sidecar/app/api/files.py` 上传不设扩展名白名单，而 `SourceView.tsx` 可预览集合是DOCX/PDF/五种图片。本项目按用户已指定的七类和100MiB限制上传与原文查看，不将它描述成灵燕完整上传能力的一比一复制，也不扩大为任意文件上传。

## 修订后的页面动作方案

继续使用上传列表 → 智能解读 → 标书制作 → 标书审查；Agent聊天只负责展示。下面所有反馈均来自真实执行、文件与请求状态，不增加模型内容审核。

1. **上传/补充来源**：保持原上传入口。状态显示上传中/已上传/未完成，成功后进入已有项目详情。格式及超限在创建项目之前拒绝；若已建项目但上传失败，保留该项目作为重传目标，重试不重复建项目。前后端同时校验，网络响应不确定先查询文件真值再决定是否重传。
2. **解读阅读**：栏目仍按原导航组织灵燕八件文件。区分读取中、读取失败、尚无成果、已有成果；读取失败不能显示“没有招标文件”，已有成果不因短暂断线消失。MD按标题、表格、重点及出处展示，业务文字不被依据按钮替换；内部编号与机器字段继续隐藏并在原文件保留。
3. **业务阶段操作**：保留灵燕目录→写作指引→关键事实与承诺→逐章正文→原工具检查/合册的依赖顺序。每个现有页签放对应主要动作；上一阶段重新生成及低频动作收拢到对应位置，不在所有页签常驻整排生成按钮。生成后显示真实文件，不要求泛化“核对结果后继续”；有多种拆分或缺承诺值时才给具体表单。
4. **目录查看/调整**：采用浦发目录的编号/标题/交付形态/概述层级，编制说明可收起，长目录提供搜索。阅读时内部编号不显示；编辑时当前节点才展开常用操作，合法性限制与源码一致。当前保留保存/取消，不引入自动保存、上下文菜单和撤销栈来扩大首个切片；跨册拖拽与整册增删仍单独待定。
5. **编辑/保存**：头部显示当前保存状态，点击保存时禁用重复提交，保存失败继续留在编辑态。错误进入顶部；当前文档仅显示状态及操作按钮，不在每个栏目下加错误段落。版本冲突保留草稿，沿用现有版本选择；读取最新会丢草稿、覆盖会替换他人版本，都明确描述。无实质修改直接退出，不弹未保存提示；不增加退出时静默强制保存。
6. **执行/停止/断线**：一个当前任务状态区展示执行阶段与停止入口；执行完成、停止、失败、等待具体选择互相区分。断线只说明连接状态，不能推断后台已停止；恢复后重读run和文件。仅在真实产物存在时开放预览/下载，run完成不能直接呈现整册验收通过。
7. **具体问题**：问题、原因、选项及补充输入在当前页面。提交中禁用重复操作，失败保留答案；同问重连保留草稿，新问题清空，陈旧提交重新对账。回答完成后收起，按需回看问题和回答，不转向聊天填写。
8. **恢复/重试**：顶部当前任务提示显示失败动作、受影响文件和一个有效恢复动作。读取失败“重新读取”，上传失败“重新上传”，保存失败“重试保存”，可重新执行的阶段使用对应原按钮；模型凭证/图片能力问题指向dsh配置，不新建模型表单。执行结果不确定先对账，不一键重发所有生成动作。
9. **检查/导出与资料**：检查页只呈现原工具工程结果及版本，未运行与未通过明确区分；合册失败保留章节成果，按册重新导出。资料失败集中提示并能重新解析；公司信息确认不移植为本项目的通用审批流程。

反馈只采用现有任务状态区、编辑头部、顶部操作提示及已有Modal，避免并存新的错误侧栏、流程向导或第二套通知系统。技术详情默认收起；输入校验靠对应控件约束，只有存在实际丢草稿/覆盖版本后果时使用已有选择对话框。

|---|---|---|

| P1 | 目录搜索、重点呈现及各类预览失败的恢复规则尚未逐项对齐 | 参考现有灵燕组件做小切片；搜索不改变目录、编号与原始关联；七类失败与资源释放验收 |

自动保存本轮不采用：它会改变“取消”的含义，且上游卸载时强制覆盖与本项目显式冲突选择不一致。保持手动保存更符合现有流程及最小实现；若后续确有频繁丢编辑的使用证据，再单独讨论，不做半套自动保存。

## 判断与反转条件

反对直接照搬的理由：灵燕以聊天和自动保存为主，运行恢复依赖自身checkpoint；其真实原件失败入口也有不足。全搬会改变我们的页面工作方式，还会引入独立配置、自动保存强制覆盖及未验证恢复承诺。

支持复用的理由：错误码区分恢复动作、加载失败不当空态、停止竞态对账、保存状态和目录视觉层级均已有代码机制，适合移入现有组件，减少自行发明。

证据更支持“复用业务与成熟反馈，保留页面操作和手动保存”。最大未知是dsh运行恢复及重试事件契约；只有实际完成副作用重入/断线恢复验收，才可改变断点按钮与恢复措辞。自动保存只有明确改变编辑语义并验证冲突/卸载行为后才重新选择。
