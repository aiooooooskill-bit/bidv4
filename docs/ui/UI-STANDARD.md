# Bidv4 全项目 UI 规范

版本：1.0 · 2026-10-12

视觉基准：已评审的资料库体验，截图保留为 `library-prototype-preview.jpg` 与 `library-prototype-representatives-pagination.jpg`；原型临时应用已在正式接入后清理。适用范围：智能解读、标书制作、标书审查、资料库，以及这些模块中的上传、编辑、预览、设置和任务反馈。

交付内容：`tokens.css` 为公共设计变量，`components.css` 为可运行的组件示例样式，`style-guide.html` 为视觉及交互示例。正式页面已按实施计划应用本标准，实际组件和样式位于项目 `src/`。示例 CSS 不是叠加在旧 CSS 后面的覆盖层。

## 1. 视觉方向与边界

采用浅色业务工作台：浅灰页面、白色面板、克制的蓝色强调、细边框、轻阴影、紧凑但清楚的表单和列表。信息层级由位置、字号、间距和留白形成。一个操作区只设置一个最主要的蓝色按钮。

统一颜色、控件、交互状态与信息层级；每个模块保留适合其任务的布局。目录编辑、阅读原件与资料管理不需要使用完全相同的列宽。

文档预览中的 Word/PDF 页面、标题、表格、页眉和字体属于文件内容，不跟随应用主题改写。项目样式仅作用于项目根节点，不覆盖 dsh 宿主的聊天区、侧栏或设置页面。

不新增主题切换、暗色主题、配置面板或 UI 组件依赖。当前 React、CSS、自有组件与 docx-preview 已足够支撑本标准。

## 3. 字体与字号

字体使用本机系统字体：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`。不在线加载字体；不要求安装 Inter。编辑识别原文、行号或技术日志时使用系统等宽字体。

| 层级 | 字号 | 字重 | 行高 |
|---|---:|---:|---:|
| 页面标题 | 26 px，窄屏 22 px | 600 | 1.4 |
| 详情标题 / 弹窗标题 | 18 px | 600 | 1.6 |
| 区块标题 | 15 px | 600 | 1.6 |
| 普通正文 / 主导航 | 14 px | 400 / 600 | 1.6 |
| 表单 / 按钮 / 表格 | 13 px | 400 / 500 | 1.6 |
| 提示 / 状态标签 / 分页 | 12 px | 400 | 1.6 |
| 文件时间 / 原文行号 | 11 px | 400 | 1.6 |
| 文档阅读正文 | 14 px | 400 | 1.9 |

操作名称、表单标签、错误文案不得使用 9–10 px。长标题允许换行；列表最多显示两行，详情显示完整标题。路径、公司名、账号等长值必须可换行、选中或查看完整内容。

## 4. 间距、形状和尺寸

间距基于 4 px：4、8、12、16、20、24、32、40。控件内部的小图标间距可使用 6 px；新页面不引入随意的 17、23、25、28 px 间距。

| 元素 | 标准 |
|---|---|
| 桌面页面内边距 | 上下 24–32 px；左右 32 px |
| 窄屏页面内边距 | 左右 20 px |
| 面板 / 详情内边距 | 24 px；窄屏 20 px |
| 列表项内边距 | 上下 16 px；左右 20 px |
| 相邻表单项间距 | 垂直 16 px；水平 20–24 px |
| 工具栏控件间距 | 8–12 px |
| 操作按钮间距 | 8 px |
| 控件高度 | 默认 38 px；紧凑操作 30 px |
| 圆角 | 标签 4 px；控件 6 px；内部区块 8 px；主面板 10 px；弹窗 12 px |
| 边框 | 1 px 实线 |
| 选中项左标记 | 3 px 蓝色 |
| 页签下标记 | 2 px 蓝色 |
| 页面最大宽度 | 1550 px，居中 |
| 顶部导航高度 | 桌面 72 px；窄屏约 62 px，可随换行增高 |

面板阴影 `0 3px 15px #1e344907`，文档纸张阴影 `0 2px 10px #25314618`，弹窗阴影 `0 25px 70px #15253e30`。普通按钮和输入框不用阴影。禁止渐变主按钮、毛玻璃、重阴影和大面积装饰背景。

## 5. 统一页面结构

默认页面顺序：主导航 → 标题与说明 → 模块页签 → 检索和筛选工具栏 → 业务内容面板。重要的保存动作位于当前编辑面板底部；任务进度位于项目标题和业务工作区之间。

### 5.1 主导航与页签

主导航负责切换四个模块；当前模块用蓝色文字和浅蓝背景。模块内部页签使用下划线样式，间距 24 px，选中状态为蓝色文字 + 2 px 蓝色线 + 600 字重。数量以紧凑浅底标签展示。

页签可横向滚动，不能挤压文字到不可读。隐藏非活动面板时保持正确的焦点与 ARIA 状态；使用 `tablist` 模式时实现方向键切换，普通导航使用链接或按钮即可。

### 5.2 左侧列表与右侧详情

公司资料、主体、授权代表：桌面左列 365 px，右列 `minmax(0, 1fr)`。写作素材左列 465 px，以容纳用途和正文摘要。1100 px 以下收敛为 310 px 左列；760 px 以下改为上下布局。

左侧固定列表标题；中间记录区独立滚动；底部固定分页。右侧固定详情标题、详情页签与保存栏，只有正文区域滚动。使用 `min-height: 0` 和 `min-width: 0` 防止内容撑破布局。

面板高度由可用容器高度决定，不照搬原型 `min-height: 680px`。分页和保存栏应在常见 1366×768、1440×900 窗口中可见；短屏无需滚过整个详情才能找到保存动作。窄屏可改成正常页面滚动。

### 5.3 文档工作区

解读、制作和审查需要保留文档对照：原件与结果、目录与正文、问题与证据。列宽可以按阅读需要设置为约 40% / 60%；保持同一套面板、工具栏、页签、状态和控件外观。

原件预览使用浅灰画布、白色纸张；预览缩放和翻页属于预览工具栏。文档内容不受应用的 `h1`、`table`、`font-family` 全局选择器影响。

## 6. 组件规则

### 6.1 按钮

四种按钮：蓝底白字主按钮、白底描边次按钮、蓝字文字按钮、红字描边危险按钮。按钮文字表达具体动作，例如「保存主体信息」「搜索素材」「开始制作」，不用笼统的「确定」承载复杂行为。

状态：默认、悬停、键盘焦点、按下、禁用、加载。禁用使用原生 `disabled`，透明度 0.45；加载保留按钮宽度，改为「正在保存…」，防止重复提交。键盘焦点使用 2 px 蓝色描边，外扩 2 px；图标按钮必须有可读的 `aria-label`。

返回、取消、下载、查看原件使用次按钮或文字按钮；同一区域不出现多个争夺注意力的蓝色主按钮。

### 6.2 表单

标签放在控件上方，13 px；标签到控件 8 px；解释放在控件下方，12 px。必填用文字「必填」表达。两列只用于短字段，说明与原文使用整行。

姓名、地址、电话、邮箱、日期使用单行输入或对应原生控件；段落说明用 3–5 行文本域，识别全文用长文本域。不能将所有缺失字段变为一排同等大小的巨大文本框。

支持默认、悬停、焦点、只读、禁用、错误、保存中状态。只读值允许复制，不等同于禁用控件。错误在对应字段附近显示具体原因，并以 `aria-invalid` / `aria-describedby` 关联。

编辑信息时明确保存和取消。存在未保存修改时，切换记录、页签或离开页面必须受到统一保护。保存成功后更新当前记录和列表；失败保留用户输入。

### 6.3 记录、表格和详情

列表项顺序：标题 → 来源 / 主体 → 简短用途或说明 → 状态标签。选中项浅蓝底 + 左蓝线；悬停用浅灰底。摘要两行截断，不在列表中显示整段 OCR、完整日志或表格源码。

表格浅灰表头、1 px 分隔线、12–16 px 单元格内边距。行内容较长允许换行；账号和标识符不任意裁切。字段编辑表使用「字段名称 / 核对值 / 出处」；技术键名应显示用户可读的中文名称。

详情页显示完整业务内容。原文、整理结果和原件应有清楚的视图入口；技术诊断折叠在「处理详情」内，不作为默认主体内容。

### 6.4 分页

所有可能增长的业务列表统一提供：记录总数、每页 5 / 10 / 20 条、当前页 / 总页数、上一页、下一页。分页放在列表底部，不因记录较少而消失。

不足一页时，显示 `1 / 1` 并禁用翻页按钮；无结果时显示 0 条、`1 / 1`。筛选、提交检索或改变每页数量回到第一页。页数减少时将页码收敛到有效范围。

翻页时详情选择同步到当前页；新增后定位到新增记录所在页。未保存修改时禁止分页。筛选总数与列表结果使用同一数据范围，不能一个是全库数量、另一个是当前主体数量。

### 6.5 状态提示和任务交互

普通说明：紧凑的浅蓝/浅灰提示。保存成功：绿色短提示。缺失资料：黄色提示 + 明确字段或回到资料库的入口。异常：红色提示 + 可执行的下一步，保留输入和上下文。

后台任务显示步骤、状态、进度和停止动作；不得仅显示加载图标让用户猜测。未知进度使用不确定状态，不能制造百分比。需要用户补充时，只展示真正缺失的字段，并按公司常用信息、人员选择、项目特定信息分类。

稳定的主体信息优先从已确认的公司档案读取；项目日期、授权范围等本次值单独确定。公司资料和代表按主体管理；写作素材全库共用。UI 统一不改变这些数据归属规则。

### 6.6 弹窗和抽屉

上传、简短编辑、参数设置用 650 px 弹窗，最大高度为可视区域的 90%，内部分为标题、滚动正文、底部动作。技术日志和来源证据用 620 px 右抽屉；常用功能不得强迫层层弹窗。

背景遮罩 `#1B2C4666`。打开后移动焦点，Tab 不越出弹窗，Escape 按当前操作状态处理，关闭后恢复触发按钮的焦点。复用现有 `Modal` 的焦点管理与堆栈，不自行增加另一套实现。

### 6.7 空、加载、失败状态

空状态解释没有内容的原因并给出下一步。无检索结果提供修改关键词或清除筛选；公司没有代表提供新增入口。加载保留面板结构和列表尺寸；失败展示重试入口，不能留空白页面。

## 7. 响应式与可访问性

| 宽度 | 处理 |
|---|---|
| 大于 1100 px | 标准左右分栏、32 px 页面边距 |
| 761–1100 px | 20 px 页面边距、310 px 左列、工具栏换行 |
| 不大于 760 px | 列表和详情上下布局、单列表单、页签横向滚动 |

窄屏优先保证标题、内容、保存和分页可达；可隐藏次要说明，不隐藏业务操作。文档工作区可以保留必要的预览滚动。响应式断点写入 CSS，不增加 JS 尺寸配置层。

支持 Tab、Enter/Space、Escape 及有明确语义的方向键操作；所有交互元素有可读名称。正文及辅助文字检查实际背景上的对比度。状态、选中与错误同时使用文字或形状表达。尊重 `prefers-reduced-motion`，不使用持续跳动的装饰动画。

此规范不是 WCAG 合规证书；最终页面需检查实际交互、对比度、键盘路径及文档预览的边界。

## 8. 在正式项目中实施

正式入口是 `src/plugin.tsx`，目前拼接 `src/styles.css`、`src/reader.css`、`src/workspace.css`；根节点是 `.bp-root.ly-root`。采用根节点限定的 `--bid-*` 变量，不重定义 dsh 宿主变量，不增加旧颜色到新颜色的兼容层。

执行顺序按端到端切片：

1. 公共颜色、字体、按钮、表单、页签、状态反馈；先完成一个能运行的正式列表和详情页面。
2. 资料库：落实列表详情、完整字段核对和统一分页；公司资料与全库写作素材使用各自业务范围。
3. 项目列表与智能解读：保留原件 / 结果对照，统一页面留白、筛选、标签及任务状态。
4. 标书制作：目录 / 正文 / 预览沿用业务布局；将缺失信息组织为紧凑表单，已维护值直接读取。
5. 标书审查、设置、上传弹窗和证据抽屉：应用同一套变量、组件状态和键盘规则。

实施时直接修改已有组件样式并删除被替换的规则，不在三份 CSS 后追加越来越多的覆盖层。复用现有 `Modal`、`NavigationGuard`、`NoticeCenter`、`SourcePreview` 和 `DocxViewer`。现有 class 可以继续作为组件选择器；class 命名不承载旧视觉兼容行为。

| 当前实现 | 按标准统一 |
|---|---|
| `styles.css` 中宿主黑色主按钮与部分蓝色按钮混用 | 所有主操作使用 `--bid-color-primary` |
| `.ly-root`、`.bp-root` 及各页面重复定义字体和间距 | 公共变量 + 组件自身布局规则 |
| 项目卡片部分按钮使用胶囊形状 | 操作按钮统一 6 px 圆角 |
| 620 / 640 / 720 / 820 / 900 / 1000 等分散断点 | 页面级收敛到 760 / 1100；仅保留有实际需求的组件断点 |
| 缺失选项平铺为大文本域 | 已有信息带出 + 短字段输入 + 真实缺失项分组 |
| 有的左侧列表没有分页 | 同一分页外观和状态规则 |

UI 改造不改变接口、文件解析、FTS/BM25、素材注入、生成流程或任务状态含义。需要新增主体档案等业务能力时单独按端到端需求实施，不假定换肤本身已经解决数据缺失。

## 9. 完成验收

- 四个模块的主按钮、表单、页签、状态和分页外观一致；无黑色主按钮、胶囊操作按钮或重复配色。
- 页面标题、列表标题、详情标题和辅助信息层级稳定，常用操作在同类位置。
- 完整覆盖空、加载、失败、禁用、处理中、未保存、成功等实际状态。
- 1366×768 和 1440×900 窗口中保存栏、分页可达；窄屏没有整页横向溢出。
- 原件预览及导出文档的内容样式正确；UI 改造不影响图表、表格、页码和原始格式。
- 未保存保护、分页、筛选、返回、弹窗关闭、焦点恢复、重试行为正确。
- 每个切片通过 `npm run check` 和 `npm run build`，并运行与改动有关的已有检查；完成实际浏览器验证。
- 被替换的旧 CSS 已删除，不存在双套主题规则、兼容映射或 fallback。

## 10. 决策依据

直接把整个项目复制成资料库的两栏布局会降低目录编辑和文档阅读的效率；直接复制原型所有 CSS 也会保留小字号、零散数值和短屏溢出。因此统一视觉和控件的收益大于统一所有业务布局。

现有资料库体验已提供可评审的视觉基准，工程侧已有 React、CSS 和可用的原件预览组件。采用这套标准的主要收益是降低不同页面之间的学习成本、消除重复样式，并保持现有后端链路。最大不确定性是完整制作 / 审查页面在长标题、大表格和等待补充状态下的内容密度；若真实任务出现关键操作不可达或证据对照困难，应调整布局和滚动，而不是推翻统一配色与控件规则。
