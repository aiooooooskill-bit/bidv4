## 通用修复

1. 要点绑定实际主文件、补遗集合、主补角色与原件内容版本。平台解读只有在来源版本一致、八份产物完成、解析稿一致且原校验通过时才能复用。独立审核要点由程序记录本轮来源；来源变化后，旧的八份文件须重新提取，不能仅改一份或依赖时间戳猜测来源。
2. 灵燕终稿检查的实际错误和警告进入同一页面问题清单，保留程序检查性质、原件和段落/表格定位，可保存处理记录。依照原检查的提示性质列为建议修改，不编造招标要求、废标或评分后果。未检查范围与说明性提示单独展示；没有独立模型复审。原生 Word 表格读取时添加的分隔符不视为 Markdown 残字，检测对象为段落及单元格中的实际文字。
3. 行号区间转换采用原引用校验器的文件锚定、同文件、斜线继承和分号分段规则，统一排除真实文件名中的 `L数字`。范围终点同样参加边界校验，避免另写一套解释器。
4. 未审核项目的列表状态不读取原件。文件内容哈希保存在项目现有 SQLite 设置存储中；跨 Python 进程复用设备、inode、大小、修改时间和变化时间均一致的摘要。文件改变时重新计算，读取期间改变则拒绝缓存。列表仅在实际完成冷恢复后再次取数。

没有新增依赖、迁移或旧报告兼容层，也没有按杭州文件名或特定条款数值写业务判断。
