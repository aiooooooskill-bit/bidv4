# 0.1.8 合并与交付范围

此次交付合并资料库文件操作、结构化字段展示、静默状态同步与独立数据目录。仅支持 DeepSeek Harness 0.2.1-rc.2，不添加旧版数据路径兼容层或自动迁移。

## 合并范围

主工作区盘点为49个已跟踪文件改动和217个未跟踪文件。以已发布0.1.7和独立数据分支为基线，合入尚未发布的资料库源码与测试；重叠的宿主适配改动去重，保留停止、原生问答续跑、UTF-8请求读取及异常卸载清理修复。历史截图和诊断材料保留本地，不作为新的源码或安装内容上传。

公司资料、写作素材和自定义Word版式支持原件更换、重新处理和删除，并校验版本、保留记录身份和归属。更换或完整重识别会按页面确认说明清除相应旧识别值；已经生成的标书文件保持原样。公司资料的AI结构化字段必须人工采用，不覆盖已经核对的字段；后台刷新保留未保存的输入和当前详情。

复核发现不同资料并发更换同名原件时，提前选择保存路径可能导致覆盖。新增公司资料和写作素材两种并发复现，修复前均失败；修复把名称分配与文件安装放在已有SQLite写事务中串行完成，并只清理本次实际创建的目标。回归逐字节核验两份原件与各自数据库SHA。

## 数据与更新

业务数据默认放在安装树旁的ooo-bidpliot-data；包管理安装与profile的node_modules并列，固定目录安装与插件文件夹并列。插件内data仅是文件系统入口。新布局下代码替换、卸载、删除整个临时node_modules和重新安装后，应自动重建入口并读取原数据库、原文件、附件和原生会话。停止任务不得自动续跑。验证不使用生产数据或真实客户任务。

构建显式指定项目tsconfig，使开发目录、固定目录及node_modules中的相同源码使用同一配置；发行物验收要求更新前后构建产物逐文件一致，不以手工替换前端文件绕过比对。

## 验收和交付

发布前执行类型检查、构建、完整JavaScript回归、完整Python回归、官方Web交付、精确TGZ安装与数据生命周期，以及实际App只读运行时的独立profile安装。最终次数、源码/包SHA和公开下载校验以该版本Release的validation.json和SHA256SUMS.txt为准；不沿用历史候选结果。

Mac为本次实测平台。Windows路径及junction实现有自动检查，Windows实机验证按用户决定暂缓，不宣称已实机通过。

生产客户端、业务数据和原Web服务不因此次交付而更新；由用户自行安装。公开上传与下载核验完成后，停止本次隔离服务并归档隔离工作区，保留交付物、校验记录和备份。
