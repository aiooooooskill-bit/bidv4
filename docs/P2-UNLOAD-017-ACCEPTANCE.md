# 0.1.7 异常卸载清理验收

本记录覆盖会话保存失败导致整插件清理短路的专项修复。插件候选版本为 0.1.7，宿主要求为 DeepSeek Harness 0.2.1-rc.2；不增加依赖或业务配置，不改变数据库结构与业务路径。最终发布另需完成正在进行的目录入口与防重入验证。

## 修复

Cordis 4.0.5 的复合 effect 使用反序串行清理，任一步拒绝后不会继续其余 disposer。保留精确的 `scope.dispose` 所有权收集，防止父级并发提前关闭业务作用域；在排空请求的回调中，通过嵌套 `finally` 依次完成运行时关闭、作用域关闭和宿主占用释放。保存失败仍写入宿主诊断，不将失败伪装成成功。

## 新增整插件回归

`tests/plugin-unload-failure.test.mjs` 使用独立应用目录、独立 DSH profile 和本机确定性模型，先正常生成八份解读并持久化原生会话，再仅对该业务 Agent 的关闭保存注入一次错误，通过真实 `entry.update({disabled:true})` 卸载插件。

旧实现稳定失败：业务作用域仍为 ACTIVE，宿主占用文件仍存在。修复后通过以下检查：

- 原始保存错误仍可观察，业务作用域彻底释放。
- 宿主占用、业务锁、Agent、句柄和待结算操作清空，页面入口返回 404。
- 原件、成果逐字节保留，原生会话事件前缀不变。
- 原宿主 Agent 仍能正常执行；移除故障后，同一进程可重新启用插件。
- 重新启用后沿用原项目和主会话，不自动调用模型；数据库 schema、版本及每张表所有类型化值保持一致，BLOB 按字节比较。

SQLite 在正常重新打开和初始化时可能改变物理页头；因此重启后的数据库校验使用完整逻辑内容，原件与成果继续使用 SHA-256 字节校验。卸载后的数据库仍保留物理哈希检查；用户安装更新时仍须备份并核对数据库与原文件。

本项独立增量审查已通过；卸载修复没有改变业务工具、数据格式或依赖。隔离环境不使用实际客户项目，也未向真实模型发送请求。

本项完整运行证据见 [验收记录](evidence/p2-unload-017-validation-20261019.json)。0.1.6 已完成的本机部署及数据保留事实见 [宿主适配验收](DEEPSEEK-021-ACCEPTANCE.md)；这些历史记录不表示 0.1.7 已经安装到正式环境。
