# 第二轮：跨阶段历史优化与隔离验证

第二轮代码已落入工作区，未更新桌面安装或正在运行的正式环境。隔离副本使用官方 `https://api.deepseek.com` 的 `deepseek-flash`；本轮没有调用本地模型。基线为包含第一轮成果的当前工作区快照，而不是 Git HEAD。

## 实施内容

- 在新业务动作第一次请求模型前处理旧阶段工具执行。通过原生 DSH 的 `compactRegion` 更新模型实际使用的会话，不修改原始会话日志，不另外启动阶段 Agent。
- 已完成且工具调用/回执完整配对的旧记录，先按原始事件完整归档到任务 `work/context/<action_id>/`，保存源会话、事件序号、SHA-256，再在上下文中替换成可回读的绝对路径。原文和当前成果继续保留。
- 所有用户消息（包括富文本、页面输入和旧压缩摘要）、问题/选项/回答所在的完整工具单元、无工具的阶段结论均保留。页面输入可能含用户的修改指示，因此没有把它当成可丢弃的系统提示。
- 保留当前轮和未完成工具单元；每个业务动作只执行一次阶段归档。审核继续下一批、更正早期批次、页面答复及冷恢复都不会触发本轮历史清除。
- 阶段指令给出当前来源、主体快照、目录读取约定和版本，提醒按现行澄清/承诺文件及原文工作。目录 section 读取明确要求完整册名、版本与路径。
- 八份解读校验、目录冻结/发布、逐章正文检查、审核条目/引用范围/关联/版本校验保持现有实现。正常压力压缩、超限恢复和工具回执裁剪继续使用原生后端。

采用已有官方压缩后端的 `summarize` 扩展点，阶段归档为确定性处理，新增的模型摘要请求为 **0**。只显式声明了原依赖树已有的 `@deepseek-ai/dsh-compaction` 同版本依赖，没有引入新的通用框架。设计参考了 [Anthropic 的上下文工程实践](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：以路径按需取证、保留任务状态、清理过期工具执行，避免过度压缩丢失信息。

## Flash 对照结果

使用包3原始原生会话的两个闭合历史前缀（解读结束、目录结束），以及同一份冻结业务数据。历史中的旧安装路径分别替换为隔离副本路径。两组通过同一原生宿主、相同模型、相同只读核验指令和现有业务工具执行，比较跨阶段请求实际携带的输入。总输入使用宿主权威 usage 的 `totalTokens - outputTokens`，**包含缓存输入**；不能只把 `inputTokens` 当总输入。

| 测量项 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| 解读历史后的交接核验输入 | 93,125 | 59,470 | -36.1% |
| 目录历史后的交接核验输入 | 428,328 | 46,589 | -89.1% |
| 两组总输入 | **521,453** | **106,059** | **-79.7%** |
| 未缓存输入 | 8,429 | 8,267 | -1.9% |
| 缓存输入 | 513,024 | 97,792 | -80.9% |
| 模型请求 | 6 | 7 | +1 |
| 模型工具调用 | 10 | 11 | +1 |
| 输出 | 3,361 | 3,741 | +380 |

优化后增加的调用来自 Flash 一次 `section` 读取提交空册名，收到程序错误后按索引完整册名纠正。错误和重试均计入结果，没有剔除。最终交接指令进一步明确不传空册名，但上表保留实测结果，不将这一提示修订推算为调用减少。两组有重复请求的缓存预热，未缓存输入与实际费用不能按总输入降幅等比例推算。

早期探索还遇到读取约定猜错、以及验收程序按日志数值序而非当前上下文位置比较归档的错误；前者补齐交接读取信息，后者按每个源事件序号逐个验证。早期探索不混入本表。最终成功对照及其所有重试均保存在证据目录。
